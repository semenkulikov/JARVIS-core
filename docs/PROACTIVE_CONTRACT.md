# Проактивность и status.json

Все расписания рассчитываются в локальном часовом поясе ОС, с учётом переходов DST.
Общие объявления включены; тренировки, protein nudge и morning briefing — opt-in.

## Unsolicited outbox

Файл `outbox/proactive-<id>.txt` может появиться без wake word:

```text
expires: 2030-01-01T12:00:00+00:00
Короткое синтетическое объявление, сэр.
```

Первая строка `expires:` необязательна; если есть — timezone-aware ISO 8601 обязательна.
Пишите файл через временное имя + атомарный rename. ID — безопасное basename, без путей.
Listener ждёт завершения записи, помещает сообщение в очередь, не перебивает текущую речь
и открывает follow-up после озвучивания.

- Тихие часы по умолчанию 23:00–08:00. Файл ждёт, пока разрешена речь, если ещё не истёк.
- Лимит по умолчанию одно проактивное объявление за 120 s; обычные ответы не лимитируются.
- DND persistent: «не беспокоить / режим тишины», обратно «можно беспокоить».
- Просроченное/некорректное объявление архивируется с причиной; spoken/stopped — тоже в `done/`.
- Стоп-фраза прекращает сообщение; не переозвучивать остановленное автоматически.
- Повреждённый state сохраняется для диагностики, автоматизация fail-closed.

## Cache schema

В `cache/status.json` атомарно записывается объект (все примеры вымышлены):

```json
{
  "updated": "2030-01-01T09:00:00+00:00",
  "text": "Краткая общая сводка.",
  "today": "Планы на сегодня.",
  "food": "Сводка питания.",
  "deploy": "Сводка проектов.",
  "protein_left": 80,
  "events": [
    {
      "id": "synthetic-event",
      "title": "Тестовое событие",
      "start_iso": "2030-01-01T10:00:00+00:00",
      "all_day": false,
      "cancelled": false
    }
  ]
}
```

`updated` и `start_iso` содержат offset или `Z`; `protein_left` — число граммов.
`text/today/food/deploy` — строки, не реальные diary-объекты. `projects` опционально может
содержать URL/репозитории для «открой гитхаб»; это приватное runtime-поле, в Git его нет.
Producer должен отдавать ближайшие события до как минимум завтрашнего полудня,
включая изменения/отмены; не путать all-day и точное время.

### Свежесть и reminders

- Текущий локальный день, age <2.5 h: читать кэш, предваряя временем снимка.
- 2.5–3 h: читать сохранённые данные сразу, предупредить и параллельно запросить `kind=status`.
- Старше 3 h / другой день / отсутствует: один ack и запрос сервера, без цепочки fillers.
- Календарь: за 15 min, только future timed events, без all-day/cancelled, только свежий snapshot (<3 h).
- Изменённые/отменённые/устаревшие pending события убираются; dedup переживает перезапуск.
- Protein nudge: opt-in, заданное вечернее время, `protein_left > threshold`, fresh <3 h, один раз в день.
- Тренировки: opt-in, пользователь задаёт weekdays (Mon=0) и время локального reminder;
  reminder относится к тренировке через 15 min, учитывает quiet/DND.

Обновление кэша и серверные proactive routines приложение не создаёт.
Факт наличия поля `events` проверяется в production-log: `status cache parsed ... events=...`.

## Morning briefing POST

После наблюдаемого user input после ≥4 h без активности, в утреннем окне,
один логический запрос в день (до трёх сетевых attempts, тот же request ID):

```json
{
  "request_id": "generated-uuid",
  "text": "Утренний брифинг",
  "trigger": "presence",
  "listener_ack": "",
  "kind": "morning_briefing",
  "local_date": "2030-01-01",
  "timezone": "UTC",
  "presence_at": 1893488400,
  "idle_seconds": 18000,
  "reply_mode": "proactive",
  "outbox_file": "proactive-generated-uuid.txt",
  "expires_iso": "2030-01-01T12:00:00+00:00"
}
```

`presence_at` — Unix seconds; timezone — настроенная метка или имя зоны ОС.
Для строгого IANA имени задайте `timezone` явно; это метаданные, а не смена часового пояса ОС.
Текст `text` служебный, ключ маршрутизации — `kind`.
Сервер пишет **один** `outbox_file` с `expires:` первой строкой; не numbered/final protocol.
Обычный старт приложения сам по себе не считается присутствием; quiet/DND откладывают POST.
`GetLastInputInfo` — индикатор keyboard/mouse activity, не проверка личности.
