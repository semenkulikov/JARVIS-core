# Объявления и status.json

Все часы считаются в часовом поясе Windows, с переходом на летнее и зимнее время. Общие объявления включены. Тренировки, напоминание о белке и утренний брифинг выключены, пока их не включат в настройках.

## Объявление без команды

Файл `outbox/proactive-<id>.txt` может появиться без слова «Джарвис»:

```text
expires: 2030-01-01T12:00:00+00:00
Короткое выдуманное объявление, сэр.
```

Первая строка `expires:` необязательна. Если она есть, время должно быть в ISO 8601 и с часовым поясом. Пишите файл под временным именем и затем атомарно переименовывайте. Идентификатор — имя файла без пути.

Помощник дожидается конца записи, ставит текст в очередь, не перебивает текущую речь и после озвучки открывает окно продолжения.

- Тихие часы по умолчанию с 23:00 до 08:00. Файл ждёт, пока говорить можно, если срок ещё не вышел.
- По умолчанию не больше одного такого объявления за 120 секунд. Обычные ответы не ограничиваются.
- «Не беспокоить» и «режим тишины» сохраняются между запусками. Обратно: «можно беспокоить».
- Просроченное и испорченное объявление уходит в архив с причиной. Уже сказанное и остановленное тоже попадает в `done/`.
- Фраза остановки обрывает объявление. Остановленное само не повторяется.
- Если файл состояния повреждён, он остаётся для разбора, а объявления из него не читаются.

## Схема кэша

В `cache/status.json` атомарно пишется объект. Пример выдуман:

```json
{
  "updated": "2030-01-01T09:00:00+00:00",
  "text": "Краткая общая сводка.",
  "today": "Планы на сегодня.",
  "food": "Сводка питания.",
  "deploy": "Сводка проектов.",
  "protein_left": 80,
  "tasks": [
    {"title": "Тестовая задача", "due_iso": "2030-01-01T15:00:00+00:00", "overdue": false, "done": false}
  ],
  "notion": "Одна-две фразы о проектах в Notion.",
  "notion_tasks": [
    {"project": "Тестовый проект", "status": "В работе", "open_subtasks": ["подзадача"], "updated_iso": "2030-01-01T08:00:00+00:00"}
  ],
  "events": [
    {
      "id": "synthetic-event",
      "title": "Тестовое событие",
      "start_iso": "2030-01-01T10:00:00+00:00",
      "all_day": false,
      "cancelled": false
    }
  ]
}
```

`updated` и `start_iso` содержат смещение или `Z`. `protein_left` — граммы, число. `text`, `today`, `food` и `deploy` — строки. Поле `projects` можно добавить: адреса репозиториев для команды «открой гитхаб». Необязательные поля для вопросов о задачах: `tasks` — все задачи на сегодня и просроченные (`title`, `due_iso` — дата или время со смещением, `overdue`, `done`); `notion` — одна-две фразы или `null`; `notion_tasks` — проекты Notion в статусах «В работе» и «На проверке» (`project`, `status`, `open_subtasks` — список строк или `null`, `updated_iso`) или `null`. Нет поля или оно битое — помощник спрашивает сервер (`kind=free`, `intent`). Это поле рабочего каталога, в Git его нет.

Сервер отдаёт ближайшие события как минимум до полудня завтрашнего дня, включая переносы и отмены. Событие на весь день и событие с точным временем не смешиваются.

### Свежесть и напоминания

- Тот же локальный день и снимок моложе 2,5 часа: читать кэш и сначала называть время снимка.
- От 2,5 до 3 часов: сразу прочитать сохранённое, предупредить и параллельно запросить `kind=status`.
- Старше 3 часов, другой день или файла нет: одна короткая реплика и запрос сервера. Цепочки «минуту, уточняю» нет.
- Календарь: за 15 минут, только будущие события с точным временем, без событий на весь день и без отменённых, только снимок моложе 3 часов.
- Изменённые, отменённые и просроченные ожидающие события убираются. Уже сказанное не повторяется после перезапуска.
- Напоминание о белке включается отдельно: заданный вечер, `protein_left` выше порога, снимок моложе 3 часов, один раз в день.
- Тренировки включаются отдельно. Дни задаёте вы (понедельник — 0), время — местное. Напоминание относится к тренировке через 15 минут и учитывает тихие часы и «не беспокоить».

Кэш это приложение не создаёт. Фиксированное расписание (раздел `schedule`: будильник, брифинг, отбой) описано ниже в «Брифинг по расписанию». В рабочем журнале факт поля `events` виден строкой `status cache parsed ... events=...`.

## Утренний запрос

После действия за клавиатурой или мышью, если до этого было не меньше 4 часов тишины и сейчас утреннее окно, уходит один запрос в день. Сетевых попыток до трёх, номер запроса тот же:

```json
{
  "request_id": "generated-uuid",
  "text": "Утренний брифинг",
  "trigger": "presence",
  "listener_ack": "",
  "kind": "morning_briefing",
  "local_date": "2030-01-01",
  "timezone": "UTC",
  "presence_at": 1893488400,
  "idle_seconds": 18000,
  "reply_mode": "proactive",
  "outbox_file": "proactive-generated-uuid.txt",
  "expires_iso": "2030-01-01T12:00:00+00:00"
}
```

`presence_at` — секунды Unix. `timezone` — метка из настроек или имя пояса Windows. Чтобы передать строгое имя IANA, задайте ключ `timezone` явно. Это подпись в запросе, пояс компьютера она не меняет. Текст в `text` служебный, маршрут выбирается по `kind`.

## Брифинг по расписанию

Запись `schedule` типа `briefing` (по умолчанию 09:00 = будильник 08:00 + 60 минут) шлёт тот же `kind=morning_briefing` за `prefetch_min` (10) минут до своего времени, с `trigger: "schedule"` и тремя полями сверху:

```json
{
  "request_id": "generated-uuid",
  "text": "Составь план на сегодня с рекомендациями: ...",
  "trigger": "schedule",
  "listener_ack": "",
  "kind": "morning_briefing",
  "style": "plan_and_recommendations",
  "local_time": "2030-01-01T08:50:00+01:00",
  "weekday": "вторник",
  "local_date": "2030-01-01",
  "timezone": "CET",
  "reply_mode": "proactive",
  "outbox_file": "proactive-generated-uuid.txt",
  "expires_iso": "2030-01-01T12:00:00+01:00"
}
```

- `style: "plan_and_recommendations"` — нужен не пересказ снимка, а план на этот день: задачи и события из всех подключённых источников, питание и тренировки, что делать и во сколько, с рекомендациями, связным текстом для голоса, а не списком.
- `local_time` — местное время запроса в ISO с поясом; `weekday` — день недели по-русски; `local_date` — дата брифинга.
- `presence_at` и `idle_seconds` в этом запросе нет.
- `expires_iso` — `catch_up_until` записи (по умолчанию 12:00): позже брифинг не читается.

Файл ответа тот же: один файл из `outbox_file`. Помощник держит его до времени брифинга и читает ровно в срок, без ожидания. Если файла нет через `server_down_wait_s` после срока, звучат «Сэр, сервер не прислал брифинг.» и короткий статус из `cache/status.json` по правилам свежести. Файл, пришедший после этого, уходит в `outbox/done` с пометкой `.late` и не читается. Сетевых попыток до `morning_max_attempts`, номер запроса тот же. Один брифинг в день, в том числе после перезапуска.

Сервер пишет **один** файл из поля `outbox_file`. Первая строка — `expires:`. Частей `.1.txt` и отдельного финального файла здесь нет. Сам по себе старт программы присутствием не считается. Тихие часы и «не беспокоить» откладывают запрос. `GetLastInputInfo` показывает, была ли клавиатура или мышь. Кто сидит за компьютером, эта функция не определяет.
